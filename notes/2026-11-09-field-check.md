# 현장 확인 메모 (2026-11-09)

현장 PC에서 3D Inspector를 처음 써 봤을 때 "화면은 뜨는데 아무 동작도 하지 않는" 문제가 있었고, 원인을 찾아 v0.1.1로 고쳤습니다. 이 문서는 현장에서 다시 확인할 것과 다음 세션에서 이어갈 논의를 정리한 것입니다.

## 1. 무엇이 문제였나

| 번호 | 원인 | 증상 |
| --- | --- | --- |
| 1 | v0.1.0 zip의 `inspector.js`에 `import` 줄이 남아 있어 페이지에 주입되는 스크립트가 SyntaxError로 실행되지 않음 (빌드가 CRLF 줄바꿈을 처리하지 못함) | 패널은 뜨지만 "로드된 프레임이 없습니다", 모든 버튼이 `Cannot read properties of undefined (reading 'job')` 오류 |
| 2 | 대시보드와 3DSpace의 호스트가 다르면 프레임에서 번들 원문을 `fetch`할 수 없음 (CORS) | 요소 선택은 "기록 없음", 모듈 보기·패치는 "모듈 없음" |
| 3 | 대상 판별이 `ENOChg`로 시작하는 폴더만 인식해 `ENOChangeActionUX`가 빠짐 | 해당 번들에서 만든 요소를 못 찾음 |

현장 증상은 1번이 원인일 가능성이 가장 큽니다. 2, 3번은 환경에 따라 생길 수 있어 함께 고쳤습니다.

## 2. 현장에서 확인할 것

1. **새 zip 적용**
   - 새 `3d-inspector.zip`을 기존 폴더에 덮어 풀기
   - `chrome://extensions`에서 이 확장의 새로고침 버튼 누르기
   - 확장 목록의 버전이 **0.1.1**인지 확인
   - 위젯 페이지를 F5로 새로고침
2. **크롬 버전**: `chrome://version`에서 111 이상인지 확인합니다. 111 미만이면 주입 방식(`world: "MAIN"`)이 지원되지 않아 같은 증상이 날 수 있습니다.
3. **진단**: F12 → 상단 **3D Inspector** 탭(안 보이면 `»` 메뉴) → 맨 위 드롭다운에서 `[번들 N]`이 가장 큰 프레임 선택 → **진단**
   - 6줄이 모두 `[정상]`이면 통과
   - `[문제]`가 있으면 그 줄의 문구를 그대로 기억해 두기
4. **요소 선택**: **요소 선택** → 위젯에서 요소 하나 클릭 → 결과의 `create` 줄에 모듈 ID(`DS/...`)가 나오는지 확인
5. **Elements 사이드바**: Elements 탭에서 요소를 선택했을 때 오른쪽 **3D Inspector** 사이드바에 같은 결과가 나오는지 확인
6. **모듈 보기**: 4번에서 나온 모듈 ID를 **모듈 ID** 칸에 넣고 **모듈 보기** → 변수명이 복원된 코드가 나오는지 확인

## 3. 결과를 말로 전달하는 법

결과를 개발 환경으로 옮길 수 없으므로, 아래 항목만 말로 알려 주면 됩니다.

- 확장 버전과 크롬 버전
- 진단의 `[문제]` 줄 문구 (없으면 "전부 정상")
- 진단 상단 근처의 `대상 번들 N개`의 N
- 요소 선택 결과: 모듈 ID가 나왔는지, "기록 없음"이 나왔는지
- 어느 단계에서 어떤 오류 문구가 나왔는지

## 4. 진단 `[문제]` 줄별 해석

| 문구 | 의미와 조치 |
| --- | --- |
| 대상 번들(ENOChg/ENOChange) 없음 | 위젯 iframe이 아닌 프레임을 선택함. 드롭다운에서 `[번들 N]`이 큰 프레임을 고르고 **프레임 새로고침** |
| 대상 번들 소스를 읽지 못함 | DevTools에서 번들 원문을 가져오지 못함. 해당 `error` 줄의 파일명을 전달 |
| 요소 기록 없음 | 페이지를 F5로 새로고침. 설치 직후 열려 있던 탭은 반드시 새로고침 |
| 이벤트 버스 PlatformAPI/ModelEvents 미연결 | 모듈이 아직 로드되지 않았거나 모듈 ID가 바뀜. 위젯을 조작한 뒤 진단을 다시 실행 |
| NLS 없음 | 언어 번들을 찾지 못함 |
| 오류 N건 | 아래 `error` 줄 참고 |

## 5. 로컬에서 검증한 것과 못 한 것

검증한 것
- 새 zip을 실제 크롬 156에 로드해 확인함
- 구성: 대시보드와 3DSpace의 호스트가 같은 경우와 다른 경우 모두
- 환경: 2026 버전 원본 로더(AmdLoader, UWA, UIKIT, PlatformAPI, ModelEvents)와 실제 ENOChg 번들 3개를 함께 로드
- 결과: 진단, 요소 선택, 이벤트, NLS 검색, 모듈 보기, 패치 검사, Elements 사이드바가 모두 정상
- 이전 v0.1.0 zip으로는 현장과 같은 증상을 재현함

검증하지 못한 것
- 실제 ENOChg 화면은 서버 API가 없어 띄우지 못했고, 테스트용 위젯 모듈로 대신함
- DataGrid처럼 비동기로 그리는 영역에서 "기록 없음"이 나오는지는 현장에서만 알 수 있음
- Local Overrides로 패치한 번들이 실제로 반영되는 전체 흐름

## 6. 다음 세션에서 이야기할 것

- 현장 확인 결과에 따른 후속 수정
- 비동기로 그려지는 영역(DataGrid 등)에서 기록이 비는 경우의 대응. 스택이 끊기는 `async`/타이머 구간을 어떻게 추적할지
- 확장 모드에서는 `getEventListeners`를 쓸 수 없어 이미 등록된 리스너(`listen(기존)`)가 보이지 않음. 현장에서 영향이 큰지 확인
- 2026 이상 버전에서 모듈 ID나 이벤트 버스 모듈이 바뀐 경우의 대응
- 검증용 E2E 하네스(현재는 세션 임시 폴더에만 있음)를 저장소에 넣을지 여부
